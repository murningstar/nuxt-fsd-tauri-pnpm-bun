## Использование

Для открытия модалок использовать `openSheetModal`

Особенности использования:

- Если необходимо программно закрыть модалку, то `openSheetModal` возвращает `close`
- Если необходимо отобразить модалку, как вложенную в другой модалке, то необходимо передать в `openSheetModal` параметр `parentSheetId`. Этот id достается из `openSheetModal` также, как `close`

Пример создания вложенной модалки и метода `close`:

```ts
const { id } = openSheetModal({
    title: 'First modal',
    description: 'Some text',
    contentSlot: () => [
        'Some text content and a UButton',
        h(UButton, {
            onClick: () => {
                const { close } = openSheetModal({
                    contentSlot: () => 'Nested sheet',
                    parentSheetId: id, // Id obtained from first modal
                });

                settimeout(() => {
                    close(); // вложенная модалка закроется автоматически через 1 сек.
                }, 1000);
            },
        }),
    ],
});
```

## Как работает внутри и почему

Есть положняк: `<UDrawer>` обрабатывает вложенность модалок у себя под капотом. И делает он это за счет пропса `nested` и provide/inject. Это значит, что мы должны класть дочерний UDrawer внутрь родительского, а также самостоятельно и явно навешивать на него `nested`.

Если мы попробуем прокинуть `nested` на `<UDrawer>`, у которого нет родителя, то `<UDrawer>` откинет внутреннюю ошибку о том, что контекст родителя не найден.

Эту проблему можно решить единственным способом - поместив дочерний `<UDrawer>` внутрь родительского. В этом проекте это сделано за счет хранения конфигов для каждой отдельной sheet-модалки в глобальном сторе вместо хранения компонентов модалок целиком (тип конфига можно посмотреть в `model/sheet-modal-stack.config.ts`).

Тип `SheetModalStackConfig` - рекурсивный (имеет свойство `childConfig` такого же типа `SheetModalStackConfig`).

И на основе этого типа сделан соответствующий рекурсивный компонент `sheet-modals-stack.vue`, который рендерит модалку на основе переданного в него конфига. И если переданный конфиг содержит свойство `childConfig`, то `sheet-modals-stack.vue` обернет в себя же и отрендерит этот дочерний конфиг.

То, каким образом собираются и менеджерятся конфиги отвечают методы `registerSheetModal` и `unregisterSheetModal` из `use-sheet-modal-stack.store.ts`. В них все сделано довольно втупую:

1.  `openSheetModal` прокидывает свои аргументы дальше в `registerSheetModal`
2.  `registerSheetModal` создает id модалки (который потом return'ит).
3.  Собирается конфиг и регистрируется в глобальном хранилище, а именно в переменой `sheetModalStacksConfigs`

И в конце концов, переменная `sheetModalStacksConfigs` используется для рендера корневых sheet-модалок. Внутри компонента `sheet-modals-renderer.vue` просто происходит цикл по всем корневым модалкам - конфиг каждой передается в `sheet-modals-stack.vue`'и. Как мы уже знаем, дочерние sheet-модалки рендерятся внутри самого `sheet-modals-stack.vue` - это значит, что в цикле нам нужны только корневые модалки.

P.S. Для чистоты файла `app.vue` обход по `sheetModalStacksConfigs` обёрнут в отдельный компонент `sheet-modals-renderer.vue`
